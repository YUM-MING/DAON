## 1. 이 모듈이 하는 일 / 하지 않는 일

```
마이크 (16kHz 모노)
   │
   └─ 0.5초마다 최근 1초를 잘라 3-클래스 분류
         ├─ fall    (낙상·충격음)  →  즉시  fall 이벤트
         ├─ speech  (대화)         →  말이 끝날 때까지 모았다가 STT → speech 이벤트
         └─ ambient (일상 소음)    →  버림
```

**하는 일**

- 소리를 듣고 "넘어지는 소리 / 사람 말소리 / 그냥 생활 소음"을 구분
- 말소리로 판정된 구간만 모아서 한국어 텍스트로 변환(STT)
- 결과를 **이벤트(dict)로 콜백 전달** — 표준출력 파싱 불필요

**하지 않는 일** (받는 쪽에서 처리)

| 항목 | 담당 |
|---|---|
| 낙상 최종 판정 (소리 + 포즈 교차검증) | 유민 · 혜원 |
| 대화 내용 이해 / 응답 생성 | 혜원 |
| 음성 출력(TTS) | 혜원 |
| 비상 알림 발송 | 혜원 |
| 화면 표시 | 유진 |

> `fall` 이벤트는 **"낙상 의심 신호"** 입니다. 최종 판정이 아닙니다.
> 설계상 소리 단독으로는 오탐이 생길 수밖에 없으니(물건 떨어지는 소리),
> 포즈 인식 결과와 함께 판단하고 "괜찮으세요?" 음성 확인을 거치는 구조를 권장합니다.

## 3. 붙이는 방법 — 이게 전부입니다

```python
from audio_module import AudioSensor

def on_event(ev: dict):
    if ev["type"] == "fall":
        # 낙상 의심 → 포즈 결과와 교차검증 후 "괜찮으세요?" 발화
        handle_fall(ev["confidence"])
    elif ev["type"] == "speech":
        # 사용자 발화 텍스트 → 대화 생성
        handle_utterance(ev["text"])
    elif ev["type"] == "voice_unclear":
        # 사람 소리는 났는데 말로 인식되지 않음 (신음·비명 가능성)
        # 낙상 직후라면 긴급도를 올린다
        handle_unclear_voice(ev["duration"])

sensor = AudioSensor(on_event=on_event)
sensor.start()
...
sensor.stop()
```

`with` 문으로도 됩니다.

```python
with AudioSensor(on_event=on_event):

```

## 4. 이벤트 스키마

### `fall` — 낙상 의심 (즉시, 지연 약 10ms)

```json
{
  "type": "fall",
  "confidence": 0.93,
  "time": 12.5,
  "score": 0.93,
  "probs": {"speech": 0.02, "fall": 0.93, "ambient": 0.05}
}
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `confidence` | float 0~1 | P(fall) — 낙상 클래스 확률 |
| `time` | float | 센서 시작 후 경과 초 |
| `score` | float 0~1 | 판정에 쓴 점수. `fall_k=1` 이면 `confidence` 와 같음 |
| `probs` | dict | 세 클래스 확률 전체 (교차검증 로직에서 쓰세요) |

> **디바운스는 모듈 안에 이미 들어 있습니다.** 받는 쪽에서 따로 구현하지 않아도 됩니다.
> 한 번 알린 뒤 5초간 중복 이벤트를 막으므로(`fall_refractory_sec=5.0`),
> **한 번의 낙상 = 한 번의 이벤트**로 옵니다. 판정 지연은 없습니다(추론 시간 수 ms).
> 근거는 `outputs/threshold_val.txt` 의 '판정 규칙 비교' 표입니다.

### `speech` — 발화 텍스트 (말이 끝난 뒤)

```json
{
  "type": "speech",
  "text": "오늘 날씨가 춥네",
  "duration": 2.1,
  "time": 15.2
}
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `text` | str | 한국어 텍스트. 빈 문자열이면 이벤트를 보내지 않습니다 |
| `duration` | float | 발화 구간 길이(초) |

### `voice_unclear` — 사람 소리는 났는데 말로 인식되지 않음

```json
{"type": "voice_unclear", "duration": 1.6, "time": 18.4}
```

분류기가 사람 목소리(speech)로 판정한 구간인데 STT가 텍스트를 못 뽑은 경우입니다.
**신음·비명·울음처럼 '말이 아닌 소리'일 가능성이 있습니다.**

#### 쓰는 규칙 (팀 합의, 2026-10-12)

**낙상 이벤트 직후 창(window) 안에서만 봅니다.** 평상시의 `voice_unclear` 는
웅얼거림·TV·마이크 잡음으로도 발생하므로 **무시해야 합니다.**

"괜찮으세요?" 질의 후 응답이 세 가지로 갈립니다.

| 응답 | 받는 이벤트 | 판정 |
|---|---|---|
| 말로 대답 | `speech` (텍스트 있음) | 내용 판단 — 긍정이면 오탐 처리 |
| **소리는 내는데 말이 안 됨** | **`voice_unclear`** | **긴급 — 의식은 있으나 말 못 함** |
| 아무 소리 없음 | 이벤트 없음 | 긴급 — 무응답 |

뒤의 둘 다 긴급이지만 의미가 다릅니다. `voice_unclear` 는 의식이 있다는 뜻이고,
무응답은 의식 불명일 수 있습니다. **보호자 알림 문구를 구분할 수 있습니다.**

```python
# 받는 쪽 구현 예시
fall_at = None

def on_event(ev):
    global fall_at
    if ev["type"] == "fall":
        fall_at = ev["time"]
        ask_are_you_ok()                       # TTS 질의 + 10초 카운트다운
    elif fall_at is None or ev["time"] - fall_at > 10.0:
        return                                 # 평상시 → 무시
    elif ev["type"] == "speech":
        judge(ev["text"]); fall_at = None      # 응답 있음
    elif ev["type"] == "voice_unclear":
        escalate("응답은 있으나 음성 인식 불가"); fall_at = None
```

> **주의**: 이것은 학습된 비명 검출기가 **아닙니다.** 비명 클래스를 따로 학습하지
> 않았고, 분류기와 STT 의 판단이 어긋난 지점을 신호로 쓰는 것입니다.
> "비명 감지 모델"로 설명하면 틀립니다.

음향으로 '비명' 클래스를 따로 학습하지 않고도 쓸 수 있는 신호입니다.
학습된 비명 검출기가 아니라 **"분류기는 사람 소리라 했는데 STT가 포기했다"**는
두 모듈의 불일치를 이용한 것이므로, 단독 근거로 쓰지 말고 낙상 이벤트와 묶어서 판단하세요.

`stt=False` 로 STT를 끄면 이 이벤트는 나오지 않습니다. 0.8초 미만 구간도 버립니다.

### 발화 종료 판정

말소리가 끊긴 뒤 **1.0초 침묵**이면 끝난 것으로 보고 STT를 돌립니다.
따라서 사용자가 느끼는 응답 지연은 `1.0초 + STT 시간`입니다 (`outputs/benchmark.txt` 참조).
15초를 넘기면 중간에 한 번 잘라서 내보냅니다.

## 5. 조절할 수 있는 값

```python
AudioSensor(
    on_event=cb,
    ckpt="./checkpoints/sound_cls.pt",  # 가중치 경로 (상대경로)
    stt=True,                # False = STT 끄고 낙상 감지만 (메모리 ~500MB 절약)
    stt_model="base",        # tiny / base / small / medium
    device=None,             # None=자동, "cpu", "cuda"
    fall_threshold=0.60,     # 낮추면 더 민감 (오탐↑ 미탐↓)
    fall_k=1,                # 최근 K개 윈도우를 보고 판정 (1=윈도우 하나)
    fall_rule="avg",         # K>1 일 때 avg(평균) / all(모두)
    fall_refractory_sec=5.0, # 한 번 알린 뒤 중복 억제 시간
    speech_threshold=0.50,
    input_device=None,       # 마이크 장치 번호. None=시스템 기본
    queue_mode=True,         # 콜백을 별도 스레드에서 호출 (권장)
)
```

### 임계값 고르는 기준

낙상은 **놓치는 쪽이 훨씬 위험**합니다. 오탐은 "괜찮으세요?" 한 번 더 물어보면 되지만,
미탐은 제품이 존재할 이유를 부정합니다.

동작점은 추측이 아니라 측정으로 정했습니다. `python eval_threshold.py --split val` 을 돌리면
τ와 N의 모든 조합에 대해 **이벤트 재현율 / 시간당 오탐 횟수** 표가 나옵니다
(`outputs/threshold_val.txt`). 상황에 맞게 바꾸세요.

| 상황 | `fall_threshold` |
|---|---|
| 시연·발표 (오탐이 눈에 띄면 안 됨) | 높게 (0.80~0.90) |
| 안전 우선 (교차검증이 뒤에 있음) | 낮게 (0.50~0.60) |

**`fall_k` 는 1 이 기본값입니다.** "연속 K개 윈도우가 모두 임계값을 넘어야 한다"는 조건을 넣으면
오탐이 줄 것으로 예상했지만, 측정해 보니 **같은 오탐 수준에서 K=1 이 더 높은 재현율**을 냈습니다.
낙상음이 0.2~0.5초로 짧아 윈도우 하나에만 제대로 담기기 때문입니다.
오탐 억제는 `fall_refractory_sec`(재알림 억제)가 담당합니다.

### STT 모델 크기

같은 한국어 문장("괜찮아요. 넘어졌는데 혼자 못 일어나겠어요. 좀 도와주세요.")으로
직접 비교했습니다. **받아쓰기 정확도는 차이가 없고 속도만 3배 차이**라 `base` 를 기본값으로 했습니다.

| | base (기본) | small |
|---|---|---|
| 인식 정확도 | 정확 (조사까지) | 정확 |
| STT 고정 지연 | **0.7초** | 2.3초 |
| 체감 응답 지연 | **1.7초** | 3.3초 |
| 모델 로드 (1회) | 1.1초 | 2.2초 |
| 디스크 | 약 140MB | 약 500MB |

측정값은 `outputs/benchmark.txt` 에 있습니다. 더 어려운 발화(사투리, 심한 잡음)를
다뤄야 하면 `stt_model="small"` 로 올리세요.

### 지연 특성 — 두 경로가 다릅니다

| 이벤트 | 지연 |
|---|---|
| `fall` | **수 ms** (분류 즉시) |
| `speech` / `voice_unclear` | 약 1.7초 (침묵 대기 1.0초 + STT 0.7초) |

**위급 신호는 기다리지 않습니다.** 낙상 이벤트는 STT 와 무관하게 바로 나갑니다.

### `confidence` 를 위험도 점수로 환산할 때

융합 로직에서 소리 모듈의 기여도를 점수로 매긴다면, 아래를 권합니다.

**`confidence` 는 보정(calibration)된 확률이 아닙니다.** 0.81 이 "81% 확률로 낙상"을
뜻하지 않습니다. 소프트맥스 출력의 상대적 크기일 뿐이라, 순서는 믿을 수 있어도
(0.81 이 0.65 보다 확실) 숫자 자체에 의미를 부여하면 근거 없는 정밀함이 됩니다.

| 방식 | 내용 | 평가 |
|---|---|---|
| **이진 기여** | 임계값(0.60) 넘으면 **고정 점수**, 아니면 0 | **권장** |
| 구간 환산 | 0.6~0.7 → 30점, 0.7~0.85 → 40점 … | 가능하나 구간 경계에 근거가 없음 |
| 선형 환산 | `점수 = confidence × 50` | **권장하지 않음** — 보정되지 않은 값을 숫자로 신뢰하는 것 |

이진 기여를 권하는 이유: 이 모듈은 **이미 임계값으로 이진 판정**을 하고 있고
(0.60 을 넘을 때만 이벤트를 보냄), 그 임계값은 val split 에서 측정해 고른 값입니다.
점수 단계에서 다시 세분화하는 것은 없는 정보를 만들어내는 일입니다.

**그리고 소리 단독으로는 발동 임계점을 넘지 못하게 배분하세요.**

| 상황 | 예시 점수 | 결과 (발동 임계 60점) |
|---|---|---|
| 소리만 | 40 | 발동 안 함 |
| 포즈만 | 40 | 발동 안 함 |
| **소리 + 포즈** | **80** | **발동** |

실환경 평가에서 비낙상 15건 중 2건 오탐(의자 끌기)이 발생했습니다
(`outputs/realworld_eval.txt`). 소리 단독으로 알림을 띄우면 의자를 끌 때마다
팝업이 뜹니다. **점수 배분으로 교차검증을 강제하는 것이 설계상 안전합니다.**

### 저사양 기기 (라즈베리파이 등)

- `stt_model="tiny"` 까지 내릴 수 있습니다. 분류기는 294K 파라미터로 가벼워
  그대로 써도 됩니다 (CPU 1회 추론 10ms 미만, 실시간의 100배 이상).

## 6. 스레드와 리소스

- `start()` 하면 **백그라운드 스레드 3개**가 돕니다 (오디오 처리, STT 변환, 콜백 호출). 데몬 스레드라 메인이 끝나면 같이 종료됩니다.
- **STT 는 오디오 처리와 분리돼 있습니다.** 변환에 0.7초쯤 걸리는데, 같은 스레드에서 돌리면 그동안 낙상 감지가 멈춥니다. 어르신이 말하는 중에 넘어지면 감지가 늦어지므로 분리했습니다. 실측으로 `push()` 최악 소요가 1500ms → 0.2ms 로 줄었습니다.
- **시작 직후 1초는 판정하지 않습니다.** 링 버퍼가 0으로 채워진 상태와 실제 입력이 섞여 가짜 신호가 되고, 그대로 두면 센서를 켜자마자 낙상 오탐이 납니다.
- `queue_mode=True`(기본)면 콜백은 **별도 스레드**에서 호출됩니다. 콜백 안에서 TTS 재생이나 네트워크 전송을 해도 오디오 처리가 밀리지 않습니다.
- `queue_mode=False`로 두면 오디오 스레드에서 직접 호출됩니다. 빠르게 끝나는 작업만 넣으세요.
- 콜백에서 예외가 나도 센서는 죽지 않습니다. stderr 에 찍고 계속 돕니다.
- **마이크는 한 프로세스만 점유합니다.** 이 모듈과 다른 코드가 동시에 마이크를 열면 실패합니다. 마이크 입력은 이 모듈을 통해서만 받으세요.

메모리 사용량(참고, CPU)

| 구성 | 대략 |
|---|---|
| 분류기만 (`stt=False`) | 약 250MB |
| + Whisper base | 약 650MB |

## 8. 트러블슈팅

| 증상 | 원인과 해결 |
|---|---|
| `FileNotFoundError: 가중치를 찾을 수 없습니다` | `checkpoints/sound_cls.pt` 를 코드와 같은 폴더 구조로 두세요 |
| `PortAudioError: Error querying device -1` | 마이크가 없거나 점유 중. `python -c "import sounddevice; print(sounddevice.query_devices())"` 로 번호 확인 후 `input_device=` 지정 |

| STT가 첫 실행에서 멈춘 듯함 | 모델 500MB 다운로드 중입니다. 2~5분 기다리세요 |

| `text` 가 계속 빈 문자열 | 마이크 입력이 너무 작습니다. OS 입력 볼륨을 올리세요 |

## 9. 알려진 한계 (보고서에 그대로 넣을 내용)

1. **학습한 낙상음은 실제 사람의 낙상이 아닙니다.** 공개 데이터셋의 충격음·파열음과 물건 낙하음으로 학습했습니다. 실제 환경에서는 성능이 떨어질 수 있습니다.
2. **STT는 사전학습 모델(faster-whisper)을 그대로 씁니다.** 노인 음성 파인튜닝은 후속 과제로 남겼습니다. 제출 기한 내에 노인 음성 데이터 확보와 학습을 끝낼 수 없다고 판단했습니다.
3. 학습 데이터에 **한국어 대화 음성이 없습니다.** speech 클래스는 영어 낭독 음성(LibriSpeech)으로 학습했습니다. "말소리인지 아닌지"를 구분하는 데는 언어가 큰 영향을 주지 않지만, 한국어 데이터로 보강하면 더 정확해집니다.
4. **TV 소리·여러 사람 대화 환경**은 별도 검증이 필요합니다.
5. `fall` 이벤트는 교차검증 전 신호입니다. 단독으로 비상 알림을 트리거하면 오탐이 발생합니다.
